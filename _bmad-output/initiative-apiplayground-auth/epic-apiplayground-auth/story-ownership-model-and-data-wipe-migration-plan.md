## Intent

**Problem:** Collections, saved requests, and history rows have no owner. Per-user data cannot be separated.

**Approach:** Add a required `OwnerId` to the three tables with a foreign key to the Identity user table. The migration clears the three data tables before adding the column and foreign key, because existing rows have no owner. The owner id is passed explicitly from `ICurrentUser` through the use cases and repository methods (option a, decided 2026-11-04). The EF global query filter is ticket 1.4.

## Boundaries & Constraints

**Always:** Migration is created only with `dotnet ef migrations add`. Other users' records behave as not found (404). Dependencies run inward.

**Never:** No EF global query filter here (1.4). No send or export owner handling (1.5). Do not change environment settings or connection strings.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Migrate empty database | No rows | Migration applies; `owner_id` NOT NULL with FK to `AspNetUsers` | None |
| Migrate populated database | Existing rows in three tables | Three tables are emptied; migration applies | None |
| Save or list without user | `ICurrentUser` returns null | 401 | `UnauthorizedProblem` / `Unauthorized()` |
| Find another user's record | Id owned by a different user | 404 | `NotFound()` |
