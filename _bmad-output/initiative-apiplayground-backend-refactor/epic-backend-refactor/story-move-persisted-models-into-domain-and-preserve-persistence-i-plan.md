## Intent

**Problem:** Persisted records are declared beside the Infrastructure-owned `PlatformDbContext` and currently have API CLR namespaces, while Domain is empty. Moving storage-shaped types without domain behavior would create an artificial ownership boundary and may destabilize EF model identities.

**Approach:** Per the owner's renegotiated direction, move the three persisted entities into the Domain project as plain typed classes with no EF references, using typed header, redaction, and query-parameter fields. Keep `PlatformDbContext`, fluent mappings, JSON value converters, and PostgreSQL stores in Infrastructure. Preserve the full CLR identity `ApiPlayground.Api.Data.PlatformDbContext`, existing migration IDs/history, table and column names, and persisted JSON data semantics; the one approved EF migration must be generated by `dotnet ef migrations add` and contain no DDL.

## Boundaries & Constraints

**Always:** Keep Domain free of EF Core and Infrastructure references. Keep `PlatformDbContext`, EF mappings, migrations, PostgreSQL adapters, and storage-only records in Infrastructure. Preserve the context's exact CLR name and current migration assembly/history. Entity classes move to Domain as plain types; do not invent domain rules, behavior, or EF attributes in Domain. Verify model-diff and migration continuity against fresh and already-migrated disposable databases. Generate any approved migration only with `dotnet ef migrations add`.

**Never:** Do not rename or relocate `PlatformDbContext`; do not hand-author migrations; do not alter schema, data semantics, migration IDs, or migration history without a specific reviewed need and approval. Do not create speculative domain abstractions or invented rules.

</frozen-after-approval>

## Design Notes

The owner clarified that Domain owns the persisted application entities around which the application is built, so the three entities move to Domain as plain typed classes. EF configuration stays in Infrastructure: `PlatformDbContext` maps the Domain types with the same table, column, index, and relationship definitions, and value converters serialize the typed fields into the existing JSON columns. The namespace change alters the entity CLR names recorded in the model snapshot, so one tooling-generated migration with no DDL records that identity change. Existing migration IDs and the `ApiPlayground.Api.Data.PlatformDbContext` identity are unchanged.
