- (decision) 2026-10-12: Use a desktop-first browser workspace with request editor and response visible side by side; on narrow desktop windows, stack the two areas vertically. Phone and tablet layouts are out of MVP scope.
- (decision) 2026-10-12: Keep the request method and URL row fixed above the editor tabs Params, Headers, and Body. Use compact Key/Value rows for parameters and headers, with add/remove controls and enabled-by-default checkboxes that can temporarily disable a row without deleting it.
- (decision) 2026-10-12: Start with an empty GET request and no URL; sending stays unavailable until a URL is entered. Use a simple JSON body editor with syntax validation, without IDE-style features.
- (decision) 2026-10-12: Show status, elapsed time, response headers, and body in the response area. Format JSON for reading and omit a raw-mode toggle. Show HTTP error responses with their status and received data; distinguish network errors/timeouts from security-policy refusals and avoid unsupported claims about root causes.
- (decision) 2026-10-12: During sending, show progress, prevent duplicate sends, and keep the previous result visible with a label that it belongs to the prior request.
- (decision) 2026-10-12: Automatically add sent requests to History; add requests to Collections only on explicit save. Offer a suggested editable name based on method and path, then allow selecting an existing collection or creating one during the same save action.
- (decision) 2026-10-12: History and Collections live in a collapsible sidebar, collapsed by default. Selecting a saved request loads its settings without sending; the response area prompts the user to send rather than showing a potentially mismatched prior response.
- (decision) 2026-10-12: Do not automatically persist sensitive header values in History or Collections; require them to be entered again before reuse.
- (decision) 2026-10-12: Use a restrained, compact, modern developer-tool visual direction, a light neutral theme, and English UI copy. Dark mode and language switching are not required for MVP.
- (decision) 2026-10-12: Include baseline accessibility from the start: keyboard operation, clear labels, visible focus, and state/error communication that does not rely on color alone.
- (event) 2026-10-12: Discovery confirmed the ApiPlayground author's local API-checking journey: configure a request, send it, inspect the observed response or failure, then find it in History or save it for reuse. The SPEC and companions are the functional contract; brainstorm ideas beyond them are not automatically MVP scope.
- (question) Exact SSRF policy, allowed destinations/test target, timeout and response-size limits, and the sensitive-header classification/persistence boundary remain open and must be resolved with the relevant security decisions before implementation.
- (question) Exact behavior for a narrow desktop browser window, history retention/limits, detailed diagnostic copy, and collection/request management actions not specified by the canonical scope remain open; do not invent additional features.
- (question) The target developer beyond the author and an objective usability check remain unvalidated hypotheses; do not claim a proven simplicity advantage or introduce a numeric ease target.
- (decision) 2026-10-13: Select the Neutral Technical light palette direction from .working/color-themes-1.html as the visual theme for ApiPlayground.
- (decision) 2026-10-13: In the response area, use Body and Headers tabs rather than showing both sections simultaneously; Body is the primary view.
- (decision) 2026-10-13: Do not add requests blocked by local security policy to History because they were never sent.
- (decision) 2026-10-13: When a saved request is loaded, omitted sensitive header values remain visible as empty rows, are disabled by default, and are labeled so the user knows to re-enter the value before using that header.
- (decision) 2026-10-13: If automatic History persistence fails, do not block sending; clearly report that the history entry was not saved. If saving to a Collection fails, keep the save form open and report the failure so the user can retry.
- (decision) 2026-10-13: Defer the exact narrow-desktop breakpoint and window behavior to the builder during implementation; preserve the agreed vertical stack when the side-by-side layout no longer fits.
- (event) 2026-10-13: User declined the optional UX Reviewer Gate; no reviewer lenses will run for this finalization.
